# 会议纪要：会议记录 / 评审会纪要 / 周会纪要

## 定位

记录一次已发生会议的**决定、异议、未决事项和行动**，让缺席者、执行者和审核者确认结论。不是逐字稿。

**排除**：会前准备 → `memo-brief.md`；非会议的状态汇报 → `status-report.md`。

## 硬约束

| 项 | 规则 |
| --- | --- |
| 写作 | 中性、精确；按议题和决定组织，不按发言顺序重放讨论 |
| 逻辑 | 会议身份（名称、时间、主持、出席、记录状态）→ 按议题：材料与必要讨论摘要 → 决定及理由 / 异议 → 未决项 → 行动 → 待审阅材料 |
| 标签 | 用稳定标签区分：已决定 / 建议 / 未决 / 待确认；建议不写成决定 |
| 事实 | 出席、决定、负责人、期限和批准状态来自会议材料或确认；草稿注明“未经确认” |
| 失败 | 摘要冒充逐字稿、讨论流水账、建议写成决定、行动不可跟踪、草稿冒充批准版、泄露无关个人信息 |

## HTML 组件配方

| 位置 | 组件 |
| --- | --- |
| 报告头 | `subtitle` 写时间、地点、主持；`audience` 写出席范围 |
| 首屏 | `summary`（本次会议形成的关键决定）+ `kpis`（决定数 / 行动数 / 未决数，可选） |
| 每个议题一章 | `lead`（议题与材料）+ `decisions`（approved / proposed / pending / rejected） |
| 行动汇总 | `actions`（负责人、截止、完成标准） |
| 未决事项 | `decisions`（status: pending）或 `checklist` |

纪要一般不放图表；只有会上审阅了数据时才用对应图表，并标来源。
