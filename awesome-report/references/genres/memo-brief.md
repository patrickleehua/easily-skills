# 简报：备忘录 / 决策摘要 / 会前材料 / 情况通报 / 专报

## 定位

让具名读者快速知悉、判断或完成会前准备。首屏直接给结论、状态或 ask，不设固定篇幅，按读者控制信息密度。

**排除**：完整论证并请求批准 → `proposal.md`（简报可作为它的封面）；按周期报告状态 → `status-report.md`。

## 硬约束

| 项 | 规则 |
| --- | --- |
| 写作 | 直接、克制；一页能读完 |
| 逻辑 | 先选模式——信息通报 / 决策请求 / 会前准备——再按“核心事项或 ask → 必要事实 → 影响与取舍 → 风险与未知 → 动作”推进；只有真实选择才写选项 |
| 事实 | 事实、数字、立场、审批状态和时点可核验；未知与假设就近标记 |
| 失败 | 首屏没有结论或 ask、把完整提案压成摘要、编造审批或立场、为了篇幅删证据 |

## HTML 组件配方

| 位置 | 组件 |
| --- | --- |
| 首屏 | `summary` + `callout`（ask：请谁在何时决定什么） |
| 事实 | `kpis`（≤4 个）+ `markdown`（≤3 段） |
| 选项（仅决策模式） | `comparison`（2–3 个选项）|
| 风险 | `risks`（≤3 条） |
| 动作 | `actions` |

简报通常用 `layout: flow`、不开导航（`"toc": false`），主题推荐 `editorial`。
