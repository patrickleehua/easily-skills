# 提案：立项 / 资源申请 / 预算申请 / 求批方案

## 定位

请求具名决策者批准、驳回或选择方向、预算、资源、试点或执行承诺。首屏必须看到：要谁在什么时间批什么。

**排除**：方向已定只讲怎么做 → `execution-plan.md`；短决策封面 → `memo-brief.md`（可作为本提案的封面）；已批准安排的发布 → 正式通知（不在本技能范围）。

## 硬约束

| 项 | 规则 |
| --- | --- |
| 写作 | 结论前置、具体、可审议；主动写代价、反例和不确定性，不用宏大背景或伪精确制造可批准感 |
| 逻辑 | 决策事项 / 决策者 / 时点 → 为什么要变（含不行动的后果）→ 目标 → 真实选项同口径比较 → 推荐 → 资源与交付 → 风险与未知 → 决策入口 |
| 事实 | 收益、成本、资源、用户证据、审批和排期可追溯；估算标假设；未批准的不写成既有承诺 |
| 失败 | 没有决策者 / ask、没有不行动基准、预设单一答案、选项口径不同、成本风险后置、编造收益或审批 |

## HTML 组件配方

| 位置 | 组件 |
| --- | --- |
| 首屏 | `summary`（请批准什么）+ `callout`（accent：决策事项、决策者、截止时间）+ `kpis`（投入 / 预期收益 / 周期） |
| 为什么 | `markdown` + `line` / `bar`（现状数据） |
| 选项 | `comparison`（含“不做”）+ `verdict` |
| 资源与交付 | `table`（资源清单）+ `timeline` / `gantt`（里程碑） |
| 风险 | `risks` / `risk-matrix` |
| 决策入口 | `decisions`（status: pending，写清选项和默认后果） |
