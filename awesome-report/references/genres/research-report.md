# 调研报告：用户研究 / 竞品分析 / 市场调研 / 访谈与问卷

## 定位

回答一个明确的研究问题，交付当前答案、证据强度和可推广边界。

**排除**：只解读既定指标 → `data-report.md`；比较特定战略或资源选项 → `business-analysis.md`。

## 硬约束

| 项 | 规则 |
| --- | --- |
| 写作 | 证据驱动、校准、术语一致；摘要独立可读；语气强度不超过证据强度 |
| 逻辑 | 研究问题与类型 → 当前答案 → 方法与样本 → 按问题或主题组织的发现 → 解释 → 建议 → 局限与下一步 |
| 事实 | 区分原始事实 / 参与者陈述、分析推断、假设和建议；方法披露到足以判断偏差；样本外推要写边界 |
| 合规 | 适用时确认委托、利益关系、同意、匿名、敏感数据用途；引用访谈原话需去标识 |
| 失败 | 没有明确问题、方法黑箱、资料摘要冒充发现、醒目个案冒充模式、相关当因果、事实与建议混写 |

## 结构骨架

1. 研究问题与结论摘要（含置信程度）。
2. 方法：研究类型、样本来源与数量、时间、工具、局限。
3. 发现：每条发现 = 结论 + 证据（数量、引语、截图）+ 适用范围。
4. 解释与建议：每条建议回链到发现。
5. 局限与后续验证。

竞品分析额外要求：对比维度统一口径，信息来源与日期逐条标注，公开信息与推测分开。

## HTML 组件配方

| 位置 | 组件 |
| --- | --- |
| 首屏 | `summary` + `highlights`（核心发现）+ `kpis`（样本量 / 周期） |
| 方法 | `table` 或 `markdown` + `callout`（局限） |
| 发现 | `items`（每条带证据与 `tags`）、`bar`（提及频次）、`donut`（样本构成） |
| 竞品 | `comparison` + `quadrant`（定位图） |
| 用户旅程 | `steps` / `timeline` |
| 框架 | `grid`（痛点 / 机会、SWOT）、`pyramid` |
| 建议 | `actions` + `evidence` |
