# 状态报告：日报 / 周报 / 月报 / 季报 / 进度报告

## 定位

按固定周期回答“相对目标和计划，我们现在在哪里、偏了多少、有什么风险、下一步是什么”。辅助上级判断，不是活动流水账。

**排除**：解释已结束周期为何如此并改变下一轮 → `retrospective.md`；以指标解读为主 → `data-report.md`；一次性高层知会 → `memo-brief.md`。

## 硬约束

| 项 | 规则 |
| --- | --- |
| 写作 | 具体、短、面向判断；不用“持续推进”“有序开展”代替产出 |
| 逻辑 | 总体状态 / 最大变化 → 对照基线的产出 → 偏差 / 风险 / 依赖 → 下一里程碑 → 需要的支持（ask） |
| 事实 | 进展用已验收产出、里程碑或有口径的指标；开会、沟通、投入时长本身不等于进展。无基线时写“无法判断是否按计划”，不默认绿色 |
| 失败 | 活动流水账、无周期 / 基线、健康色无判据、风险被埋、猜测根因冒充事实、下一步无里程碑、ask 不可执行 |

## 各周期差异

| 周期 | 定位 | 篇幅 | 结构 |
| --- | --- | --- | --- |
| 日报 | 当天动作 + 明日安排，供直属上级扫一眼 | ≤300 字 | 今日完成（3–5 条，动作 + 结果）→ 进行中 / 未完成（含原因）→ 明日计划（1–3 条）→ 风险 / 需协调（没有写“无”） |
| 周报 | 辅助决策：进展 / 风险 / 下周计划 | 500–800 字 | 核心结论（1–2 句）→ 关键进展（按优先级、带数据）→ 风险与需要的支持 → 下周计划（≤5 条，含完成标准和时间） |
| 月报 | 月度汇总 + 趋势 + 下月重点，给上级和隔级 | 800–1500 字 | 月度总览 → 关键数据（环比 / 同比表）→ 重点事项（只展开 3–5 件）→ 问题与对策 → 下月计划（区分必须 / 应该）与需要的决策 |
| 季报 | 对照季度目标的达成评估 + 下季策略 | 按需 | 季度结论 → 目标达成（逐条：目标 / 实际 / 差距）→ 亮点与不足 → 下季目标与策略调整 → 资源请求 |
| 项目进度报告 | 项目群 / 专项的阶段状态 | 按需 | 总体健康度 → 各工作线状态 → 里程碑偏差 → 风险与依赖 → 变更与决策请求 |

写月报先汇总当月周报，写周报先汇总本周日报——先找上游材料，找不到才让用户口述。

## 写法要点

- 优先写相对上期、相对承诺的**变化量**；稳定低风险项一句带过或链接原记录。
- 风险三要素：描述 + 影响（延期几天 / 阻塞什么）+ 需要谁在什么时间做什么。
- ask 写明对象、事项和需要的时间；关键数据延迟时写最近可用时间及对判断的影响。
- 冲突数据并列保留并标 `[口径待核]`。

## HTML 组件配方

| 位置 | 日报 | 周报 / 进度报告 | 月报 / 季报 |
| --- | --- | --- | --- |
| 首屏 | `summary` + `highlights` | `summary` + `highlights` + `kpis` | `summary` + `highlights` + `kpis` |
| 总体状态 | — | `rag`（附判据） | `scorecard`（目标达成）或 `gauge` |
| 进展 | `items` | `table`（status 列）/ `items` | 重点事项用 `items`，趋势用 `line` / 分组 `column` |
| 排期 | — | `gantt` 或 `timeline` | `timeline`（里程碑） |
| 风险 | `callout` 或 `risks` | `risks` | `risks` + 必要时 `risk-matrix` |
| 下期 | `actions` | `actions` | `actions` + `callout`（需要的决策） |

示例：`assets/examples/daily-report.json`、`weekly-status.json`、`monthly-manufacturing.json`。
