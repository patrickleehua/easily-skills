# 工作总结：年终 / 半年 / 述职 / 转正 / 晋升材料

## 定位

对较长时期（季度以上）的个人或团队工作做总结与评价，读者要据此判断“做成了什么、价值多大、能力如何、下阶段怎么安排”。常用于绩效评估、述职答辩、晋升评审。

**排除**：只报本周期状态 → `status-report.md`；只针对一个项目提炼经验 → `retrospective.md`。

## 硬约束

| 项 | 规则 |
| --- | --- |
| 写作 | 成果导向、量化、诚实；每条成果写“做了什么 → 结果 → 价值 / 影响”，不写职责说明书 |
| 逻辑 | 总体结论（一句话概括这段时期）→ 目标达成 → 3–5 项代表性成果 → 能力成长与不足 → 下阶段目标与需要的支持 |
| 事实 | 成果须有可核查证据（上线记录、指标、客户反馈、评审结论）；团队成果写清本人角色，不把团队成果写成个人成果 |
| 失败 | 罗列日常事务、只有投入没有结果、只写优点、成长写成口号、下阶段目标不可衡量 |

## 结构骨架

1. 总体结论：一句话 + 3 个关键数字。
2. 目标达成：对照年初 / 期初目标逐条列出目标值、实际值、达成情况；未达成的写原因。
3. 代表性成果：只展开 3–5 项，每项用 STAR 或“背景 → 行动 → 结果 → 价值”，写清本人角色。
4. 能力与不足：各 1–3 条，每条配一个具体事件作证据；不足写改进动作。
5. 下阶段计划：目标（可衡量）+ 关键举措 + 需要的资源或支持。

述职 / 晋升场景把第 3、4 项对齐到职级标准的维度（专业深度、影响范围、协作、带人）。

## HTML 组件配方

| 位置 | 组件 |
| --- | --- |
| 首屏 | `summary` + `kpis`（3–4 个关键数字）+ `highlights`（代表成果） |
| 目标达成 | `scorecard` 或 `gauge` |
| 代表性成果 | `items`（每项带 `tags` 标能力维度）或 `grid` |
| 过程 | `timeline`（关键节点） |
| 能力与不足 | `grid`（优势 / 待改进）或 `comparison`（对照职级标准） |
| 下阶段 | `actions` + `callout`（需要的支持） |
