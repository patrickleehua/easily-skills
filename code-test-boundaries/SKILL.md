# 代码与测试投入边界

先满足当前契约、兼容与必要保护，再在充分的方案之间选择新增行为、结构和长期维护负担较小的方案。**充分由风险决定，最小在充分之后比较。**不按代码行数、测试数量、生产与测试代码比例或覆盖率配额做决定。

## 按任务取用

- 正在开发、测试或评审：用本入口判断，只执行当前角色获准的动作。
- 要接入专家、仓库提示词或新 SOP：读 [接入方法](references/adopt-into-sop.md)，再选一份角色片段；无需让所有专家加载本技能。
- 遇到取舍争议：按需读 [决策案例](references/decision-cases.md)。
- 要核对设计理由、公开参考和能力边界：读 [设计与公开参考](references/design-and-sources.md)。

本技能提供专业判断。原有权限、必做检查、指定专业方法、输出合同、流程状态、复审轮次及人工出口继续适用。不得用本技能自行放宽它们，也不新增一套执行协议。

## 从当前契约找到证据缺口

先看当前需求、验收、差异、真实入口和相邻检查，判断本次改变了什么可观察行为。区分业务必须、项目必做项与可选增强；验收冲突影响正确性时，把具体分歧交给原决策渠道，其余独立工作继续。

需要组织复杂变更时，用下面的关系定位缺口，沿用现有计划或验证说明，不另建必填台账：

> 契约 C：必须发生／不能发生什么 → 风险 R：哪种可达错误会破坏它 → 证据 E：用什么独立判据在何种条件下识别错误。

风险看错误后果、可达性、影响范围和可逆性；同时沿上下游检查契约是否被破坏。低概率不自动豁免高后果风险，低行数也不代表低风险，无关的想象风险不扩大本次范围。

证据需对应本次相关代码、配置、输入与环境。先核已有证据的适用性：同一风险已有充分判据且证据仍有效时，直接引用，不重复建设测试设施或仅为换一种形式重跑。相关改动使证据失效时，在最终版本补跑受影响检查；未受影响的有效证据继续复用。历史通过只能支持其适用范围，不能把“未发现问题”当成全部行为正确的证明；项目明确要求重跑的检查仍须执行。

## 决定生产代码的增量

- 在正确责任边界修根因，优先复用已有入口和稳定结构。充分方案之间比较新增分支、状态、接口、依赖与维护成本；少行数不是目标。
- 新抽象、配置、框架、依赖、兼容分支须解决当前具体问题，或满足明确的现行约束；“将来可能复用”本身不够。
- 保留契约必需的错误处理、校验、安全、并发、兼容和可观测性。不要为减少代码省掉必要保护，也不要扩大到无关修复。

## 分开决定四类投入

| 决定 | 判断依据 |
|---|---|
| 必要验证 | 用已有检查和指定方法补当前证据缺口，完成项目必做项；需要验证不等于需要新写测试 |
| 新增永久测试 | 现有判据有缺口，或将人工判据自动化有明确持续回归价值，且值得长期维护 |
| 临时诊断 | 为定位具体疑点做最小探测；疑点解除即停，不自动进入正式测试集 |
| 交付证据 | 复用上述工作的有效输出，说明版本、条件、结论与缺口；不为留证另造一套检查或报告设施 |

四类投入分别决定，不能自动叠加。一次已有测试的运行结果可以同时满足必要验证和交付证据；一次临时诊断可以留下证据而不保留为永久测试。同一风险已有充分判据时，除明确的持续价值或项目要求外，不再增加等价断言、跨层副本或包装设施。

每个新增永久测试应能回答：保护哪条契约，哪种具体错误会使其失败，相对已有检查补什么缺口，或把已有人工判据自动化能带来什么持续价值。预期来自权威需求、协议、独立计算或事实，不能照抄被测实现。

选能观察风险且成本合理的层：核心规则的组合主要放在核心层；接缝验证映射、调用、持久化与副作用；真实 UI、协议、并发和宿主行为保留对应证据。同一判据不机械重复到每层；层间失效机制不同时仍须分别验证。

等价输入优先参数化或复用夹具，不合并不同边界、状态和错误机制。mock 可隔离无关依赖，不能替换正在验证的真实交互。新增设施须有当前风险依据；不因本次测试多就删除历史测试、弱化断言或修改产品契约。

## 测试失败时先核对依据

失败可能来自产品、测试本身、环境或契约歧义，先保留原始结果，再依据独立合同归因；不能只为变绿修改预期。

- 产品行为违反已确认契约：在授权内修产品，复跑原失败场景及受影响回归。
- 测试预期、夹具、定位器或等待方式与现有契约不符：在测试写范围内按现有契约纠正，记录原错误、依据及改动，重跑受影响检查。纠正测试不等于变更需求，无需虚构需求变更；也不能从产品当前输出反推预期或把产品缺陷伪装成脚本问题。
- 契约本身有冲突、缺失或确需改变：由原决策渠道处理；不能由本技能裁定新业务规则。环境问题按下节处理。

修正执行方式后得到的通过，只证明修正后实际执行的行为；不能倒写原始记录，也不等于修过产品。

## 环境或工具不足

先做最小能力探测：能否运行、能否观察、能否独立判定。确认具体工具、输入、服务、设备、权限或判据缺口，保留障碍和原始结果，不凭猜测认定产品有错。

在既有工具、授权及角色写范围内，针对已知原因做低成本、可回退的恢复。恢复不自动授权安装、提权、改环境基线或越权改业务代码。替代证据须说明覆盖的行为、版本与前提；模拟、局部检查和历史结果不冒充当前真实运行。

分别给出以下结论，写进原有交付说明即可：

1. **实现判断**：契约、真实入口、调用链、边界和失败路径支持什么。充分、独立、可复核的证据可支持“在所列前提和范围内，实现符合契约”；未知前提单列，不能只说“看着合理”。
2. **运行证据**：哪些检查实际通过、失败、未执行，覆盖哪个版本与条件。环境归因不自动改写原始失败或验证记录的状态。
3. **专业完成度**：当前角色与方法合同要求的工作是否完成；完整失败分析可能构成专业完成，仍不代表测试通过或产品验收通过。

环境障碍本身不要求重写有依据的实现或堆模拟测试。必要真实验收仍缺证据时，保留具体交付缺口并沿原合同处理；非必需增强只列风险／建议。

缺口已确认，且没有新线索或授权内可行恢复办法时，停止无意义重试，继续独立工作。留下受影响验收与版本、障碍及已尝试办法、已有结论与前提、最小缺失条件、恢复后的复跑入口；不要笼统把整项任务挂为“等环境”。

## 收口与重新打开

必要检查完成、最终相关输入上的证据充分、已发现的必要缺口已处理后，即停止加例、扩大设施或重复运行。重开须指出具体触发：相关改动使证据失效、新失败或相关风险暴露缺口，或原验收另有要求；按实际影响补跑，影响覆盖全套或项目明确要求时再全量。

不默认增加“证明测试有效”的配套工具，更不递归建设验证这些工具的工具。有具体误报、漏报或观察能力疑点时，优先用已有失败样本、权威状态或最小探测确认；疑点解除即回到原验证，不扩成新的验证平台。项目明确要求的测试有效性检查继续适用。

评审要求返工时，指出具体必要契约、缺失证据和会漏掉的错误；简化建议也须有当前维护成本依据。额外增强不升级为新阻塞；按原轮次与出口收口。条件不足的交接不是全绿验收，也不是永久重试的理由。

普通改动不另交投入评估报告。有争议的取舍在既有输出中用一两句话说明依据、证据范围与缺口。
