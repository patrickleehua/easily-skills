## 实现与验证投入

先满足当前契约、兼容和必要保护，再在充分方案之间选择新增行为、结构和维护负担较小的方案。沿正确责任边界修根因，复用已有入口；新抽象、配置、依赖或兼容分支须解决当前具体问题，不只为未来可能复用。不得为少写代码省掉必要校验和错误处理。

验证投入按可达风险与现有证据缺口决定，不按行数、用例数或生产／测试代码比例。分开决定必要验证、新增永久测试、临时诊断和交付证据，不自动叠加；已有运行输出可直接用于交付。先核现有回归与证据是否适用，同一风险已有充分判据且证据仍有效就复用，不再建等价设施；证据失效才补跑受影响检查，项目明确要求的重跑除外。新增永久测试须有契约、具体错误及持续回归价值，预期来自独立依据。核心规则与跨层接缝各在适合的层验证；不机械复制，也不以 mock 代替必要真实交互。

测试失败先保留原结果，区分产品、测试、环境和契约问题。在既有写范围内，可依据现行契约纠正错误预期、夹具、定位器或等待，说明依据并复跑受影响检查；这不等于变更需求，无需虚构需求变更。不能复制产品当前输出改预期或掩盖产品缺陷，真实业务规则变化仍交原渠道。

临时诊断不自动永久保留；本规则不授权删除历史测试、改验收或弱化断言。必要检查完成、最终相关输入上的证据充分且必要缺口已处理后收口。重开须有具体证据失效、新失败或相关风险缺口，补跑受影响范围；原验收另有要求时遵从。不默认扩建“验证测试有效”的工具，更不递归验证这些工具；具体误报／漏报疑点用最小探测排除即停，明确必做项仍须完成。

环境不足时，最小探测确认运行、观测和判据的具体缺口，在原有工具、权限与写范围内针对已知原因恢复。没有新线索或可行恢复办法就停止重复尝试，继续独立工作；不凭环境障碍重写有依据的实现、堆模拟测试或擅装工具、提权。

分别说明实现判断、运行证据与专业完成度。契约、真实入口、调用链、边界和失败路径的独立证据充分时，可给“在所列前提和范围内，实现符合契约”的源码结论；未知前提和运行未验面照实列出。替代证据只支持其实际范围，环境归因不改写原始失败／未验为通过。

在既有输出中留下受影响验收与版本、障碍和已尝试办法、已有结论及前提、最小缺失条件和复跑入口。必需真实验收缺失仍列交付缺口，非必需增强不升级为阻塞。原写范围、必做检查、专业方法、返回合同与轮次出口继续适用，普通任务不另交评估表。
