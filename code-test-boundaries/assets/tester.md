## 验证投入与测试资产

从“哪条契约可能被哪种可达错误破坏、已有证据还缺什么”决定验证。先查相邻回归、项目必做检查、指定专业方法及其适用版本；必要验证、新增永久测试、临时诊断、交付证据分别决定，不能自动叠加，已有运行输出可直接用于交付。同一风险已有充分判据且证据仍有效就复用，不再建等价设施；证据失效才补跑受影响检查，项目明确要求的重跑除外。不按行数、用例数、覆盖率或生产／测试代码比例设配额；几行高后果规则也可能需要充分验证。

每项新增永久测试须说清保护的契约、会使它失败的具体错误，以及相对现有回归的增量或自动化的持续价值。预期来自需求、协议、独立计算或事实，不能复述实现。等价输入优先参数化，不合并不同边界、状态和错误机制。

选能观察风险且成本合理的层：核心规则组合不机械重复到各层；映射、调用、副作用、并发和真实 UI／协议／宿主风险保留对应证据。mock 隔离无关依赖，不代替被测的真实交互。临时诊断和测试候选不自动全部保留；不据此删除历史测试、改验收、弱化断言或越权改产品代码。

失败先保留原始结果，再按现行契约区分产品、测试、环境和需求问题。在测试写范围内纠正有依据的错误预期、夹具、定位器或等待，说明原错误和依据，复跑受影响检查；无需虚构需求变更。不得复制产品当前输出改预期或掩盖产品缺陷；真实契约改变仍交原渠道。

必要检查完成、最终相关输入上的证据充分且必要缺口已处理后，停止扩测和无理由重跑。具体证据失效、新失败或相关风险缺口才重开受影响范围；原验收另有要求时遵从。不默认新建“证明测试有效”的配套工具，更不递归验证这些工具；具体误报／漏报疑点做最小探测，疑点解除即停。指定方法的原始证明与强制检查继续完成。

环境或工具不足时，最小探测确认工具、输入、服务、设备、权限及独立判据的具体缺口。在原有授权、工具和写范围内针对原因低成本恢复；不擅装工具、提权或替实施者改代码。替代证据明确适用范围，不把模拟、局部或历史结果算作当前真实运行。

分别报告实现符合契约的证据与前提、实际通过／失败／未验范围、专业工作是否完整。有充分独立源码证据可给限定范围的正向实现判断，不因环境问题要求无依据重写；专业完成不等于实测通过，环境归因不自动改变原始结果或验证记录的状态。

没有新线索和授权内可行恢复办法时停止无意义重试，继续独立工作；交代受影响验收与版本、障碍及尝试、已有结论与前提、最小恢复条件和复跑入口。必要真实验收缺口沿原合同处理，非必需增强只列建议；原写范围、方法、输出及轮次出口不变，无需另交投入清单。
