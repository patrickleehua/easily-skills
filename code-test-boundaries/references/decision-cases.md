# 决策案例与误用检查

用于解释和检查规则，不是实际代理评测结果；案例中的运行状态均为假设。按真实任务契约调整，不能把案例当作新的必做测试清单。

| 情形 | 合理取舍 | 需要拦住的误用 |
|---|---|---|
| 注释更正或可逆文案修改 | 用相应现有检查；若影响显示，核实际显示 | 另起测试设施凑数量；或一概不验证 |
| 行为不变的重构，当前回归能识别相关错误 | 在最终改动上运行相关回归与必做项，无缺口不强制新增 | 用旧版本绿结果；机械复制同一断言 |
| 同一风险已有充分判据和仍有效的运行证据 | 引用适用版本与条件，直接用于当前判断和交付；完成明确要求重跑的检查 | 为换报告格式、加包装脚本或多一层断言重复建设 |
| 临时查询已定位问题并提供本次证据 | 保留必要输出；是否永久化另看持续回归价值 | 自动新增脚本、永久测试和一套证据设施 |
| 需求规定上限为 20，测试误写为 10 | 按现有需求修正错误预期，保留依据并复跑相关检查 | 要求虚构一次需求变更；或按产品当前输出随意改预期 |
| 夹具角色错误或定位器选中了相邻控件 | 在授权内纠正准备／执行方式，复跑受影响场景 | 把脚本失败算作产品缺陷，或跳过断言后算通过 |
| 五行金额／权限修复 | 从独立契约补边界、失败与必要组合判据 | 为满足测试／实现比例减少关键验证 |
| 新增抽象仅为了以后也许会用 | 用现有职责与结构完成当前充分方案 | 为控制代码量强压必要解耦；或反过来提前造框架 |
| 多个等价输入，另有不同状态／错误机制 | 等价类参数化，差异机制分别保留 | 一种输入一套夹具；全部压成正常路径 |
| 业务核心与 API／前端都存在 | 核心测规则，接缝测映射和副作用；真实交互按契约验收 | 各层完整复刻规则组合；两头单测绿即宣称整链路通过 |
| mock 写死服务成功，而风险是调用真实服务 | mock 只支持局部逻辑，另保留真实接缝证据 | 用桩的成功证明服务协议或鉴权成功 |
| 仅改布局，构建通过 | 保留原本要求的实际页面／客户端检查 | 用构建替代视觉和交互验收 |
| 当前缺环境，但独立源码证据充分 | 给带范围和前提的实现结论，实际运行保留未验 | 自动否定代码、重写实现；或冒充实测通过 |
| 服务缺失且真实联调明确必做 | 完成独立工作，列必要证据缺口和恢复入口，沿原流程交回 | 无限等待全绿；或悄悄免掉联调 |
| 没有可信预期值／协议 | 先补权威判据；允许判断已知局部行为 | 从实现复制输出充当预期，自证正确 |
| 命令超时被判断为环境原因 | 记录超时原结果及归因证据，沿用目标流程的验证结果分类 | 自行把失败改为未验或通过 |
| 仅未跑非必需兼容平台 | 列未验范围与后续建议 | 将所有想象中的平台变为新门禁 |
| 必要检查已足够，后续又改相关配置 | 重开受影响证据；其他有效证据无需重复 | 永久循环跑全量；继续使用已失效结果 |
| 怀疑断言误报／漏报，已有样本可独立核对 | 用样本或最小探测解除具体疑点，回到原检查后收口 | 新建验证测试的框架，再建验证框架的工具 |
| 专项维护方法要求先红后绿与全量回归 | 完成专门合同，通用精简只作用于非强制增量 | 以已有覆盖豁免强制回归 |
| 复审追加本轮无关优化 | 按原复审范围与严重度列建议 | 无理由反复打回，突破原轮次出口 |

## 一个轻量关系例子

契约：同一支付回调不能重复记账。风险：重复／并发到达会产生两笔账。证据：独立账务判据下，同一业务标识只有一次有效记账；还需核事务或约束在真实持久化边界生效。核心函数的重复调用单测能支持局部行为，不能独自证明多进程并发的数据库约束。

这是层次选择示例，新增多少测试取决于已有回归、故障机制与当前验收，不设固定数量。

## 真实试用时看什么

同一任务对比实际保留的契约保护、漏检与误阻塞、无价值资产、无理由重复运行及环境交接是否可恢复。记录宿主、提示词版本、任务版本与真实结果，区分相关性和因果；模型、任务难度变化都可能影响结果。

只用目录、标题、措辞匹配通过，或只观察测试变少，都不足以证明本技能改善了交付。
