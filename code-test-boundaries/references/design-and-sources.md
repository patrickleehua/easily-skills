# 设计依据与公开参考

## 设计建议与推论

以下是本技能采用的工程判断，实际接入时须结合目标任务、项目约定与证据评估。

| 设计选择 | 判断依据 | 适用边界 |
|---|---|---|
| 用契约—风险—证据关系控制投入 | 代码长短不能直接说明错误后果或证据是否充分 | 业务判据来自需求与协议；本技能不自行定义产品需求 |
| 分开必要验证、永久测试、临时诊断与交付证据 | 一次执行可支持多个用途，不应自动叠加资产；有效证据可复用，人工判据也可能值得自动化 | 保留项目强制证明，不授权删除历史测试或弱化断言；有依据地纠正测试错误不等于变更契约 |
| 按实施、测试、评审职责选片段 | 这三类工作分别决定代码增量、验证判据和充分性裁决 | 按本次实际职责选择，不要求每种职责各建一个代理 |
| 分开源码判断、运行证据和工作完成度 | 环境障碍本身不能证明实现错误；合理源码判断也不能证明真实环境已经运行通过 | 正向结论须有独立、可复核依据和明确前提，必要真实验收缺口仍保留 |
| 短入口与按需资料分开 | 当前任务只需读取能改变本次决定的规则 | 角色片段可单独接入，不强制读取全部案例和参考 |
| 使用纯文档，不增加执行框架 | 当前能力是上下文相关的专业取舍，没有必须新增的确定性工具动作 | 出现重复、可测的自动动作后再评估脚本和执行层 |

以上公开资料用于查阅格式与宿主机制。契约—风险—证据模型、测试保留规则及环境受限判断属于本技能的工程建议，不代表标准条款或厂商效果承诺。本文不提供产品排名、市场占比或代理行为对比结论。

## 能力边界与后续验证

- 本技能提供可审查的判断规则和角色片段；执行权限、强制门禁、状态管理和证据保存应由目标工具或流程实现。
- 结构检查只说明文件组织和元数据符合检查规则；案例推演只检查语义与明显冲突，不能证明模型遵守率、测试减少比例或交付质量改善。
- 文本可供不同宿主适配。自动发现、工具可用性、权限、安装和实例加载需在目标宿主实际验证；本技能不预设已经完成跨宿主验收。
- 根据真实漏检、误阻塞、无价值维护和失实报告修正规则，避免把每个案例都扩成全局流程。
