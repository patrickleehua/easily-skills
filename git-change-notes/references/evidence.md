# 证据与范围规则

## 固定上下文

先确定 `repo`、`scenario`、`mode`、`source/target` 或 `base/head`、组件及语言。缺失字段优先从任务、仓库规范与当前状态推断；不要为可选风格反复提问。

读取 `git status --short`、相关版本文件和最近同类说明。将命名 ref 解析为 commit 后记录具体对象 ID；将用户输入作为工具参数传递，避免未经校验的 shell 插值。存在本地访问时无需为了获取相同事实而联网；使用托管平台特有信息时再调用对应能力。

## 按场景选择范围

| 场景 | 只读定位命令示意 | 注意 |
| --- | --- | --- |
| 当前暂存提交 | `git diff --cached --stat`；`git diff --cached --` | 仅读实际 staged patch；初始提交没有 HEAD 也可读取 |
| 用户指定未暂存修改 | `git diff --stat`；`git diff --` | 不自动加入暂存；untracked 需另行读取，不能假定进入提交 |
| 已有 commit | `git show --format=fuller --stat REF`；`git show REF --` | 遇到 merge commit 需显式选择父提交或按实际合并结果分析 |
| 未合并 PR/分支 | `git merge-base TARGET SOURCE`；`git diff TARGET...SOURCE --`；`git log TARGET..SOURCE` | 三点 diff 表示共同祖先到源分支；不等于两个分支最终树的差异 |
| 已完成普通 merge | `git diff MERGE^1 MERGE --`；结合源分支记录 | 第一父提交到最终树能涵盖冲突解决；squash 无第二父提交 |
| release / changelog | `git diff BASE HEAD --`；`git log --topo-order --format=fuller BASE..HEAD` | 两个快照的净变化为主，日志用于追溯；不要只读 first-parent 或只读标题 |
| tag annotation | `git rev-parse TAG^{commit}`；`git show TAG` | 已有 tag 必须核实对象类型和目标；新 tag 的目标不能默认猜成 HEAD |

命令仅作定位示意，不直接复制未替换的变量。遇到浅克隆、缺失对象或不同发布线时，将缺失范围说明为限制，不声称已完整核实。补取数据只在环境允许且属于当前任务时进行。

## 选择 release 基线

1. 优先使用用户显式指定的上一版本或比较范围。
2. 否则读取当前组件的 release 配置、历史 release 与 tag 命名规则。
3. 在同组件、同发布线且能与目标正确比较的候选中选择上一已发布版本；检查可达关系，不使用全仓最新 tag 或提交日期替代版本顺序。
4. 对预发布与正式发布，遵循该项目的基线策略；不能把 RC 自动当作全部正式版发布说明的基线。
5. 无法唯一确定时列明候选与差异。可以继续整理变更素材；在形成依赖该范围的正式文案或执行发布前取得明确范围。
6. 首次发布若没有基线，以可确认的首次发布范围说明；不伪造 previous tag 或 compare 链接。

多包仓库同时读取目标包、影响它的共享模块，以及对应 CLI、schema、运行时和安装流程。不要仅按包目录过滤而漏掉共享行为；不要把其他包的独立变化归入当前组件。发布日期取已知记录或用户指定值，草稿未知时省略。

## 从日志映射到最终变化

- 阅读实质变化对应的 patch 或接口说明，核对其效果仍存在于目标。
- 将实现、回归测试和文档的同一结果聚合到一条变化；保留多个真实来源作为佐证。
- 排除完全回滚且没有残留效果的变化；部分回滚、兼容性影响或迁移行为仍需说明最终状态。
- 遇到 cherry-pick、重复提交或 merge 转述时，按最终效果去重；不能仅凭标题相同就合并不同修复。
- 对 squash 使用新提交及可读取的原 PR 作来源，不强制保留已经不可用的旧 hash。
- 根据真实消费者影响识别 breaking，即使历史标题仅写 `fix` 或 `refactor`。

## 来源和验证

仅在远端 owner/repo 和托管平台已确认时构造 commit、PR 或 compare 链接。不要把带凭据的 remote URL 输出或复制进说明。对托管平台不明确的远端保留已知 hash/编号，避免猜测 URL 格式。

每个验证声明至少对应真实命令或检查名称、结果、以及覆盖的 patch/commit：

- 有测试文件或名为“test”的 commit：只能说明新增/调整测试。
- 运行退出成功：说明具体本地检查通过，不推断完整测试通过。
- 读取对应 commit 的 CI 检查：才能说明该 CI 状态。
- 环境限制或未执行：明确写出未运行及已知原因，不把计划当结果。

证据不足时，保留可核实部分并在交付正文之外说明缺口。只有执行确实依赖缺失字段时才暂停该执行步骤。
