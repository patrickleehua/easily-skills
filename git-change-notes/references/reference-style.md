# 参考风格与适配边界

参考来源：[rea-agents-6.3.0 release](https://github.com/morluto/rea/releases/tag/rea-agents-6.3.0)。本规则依据 2026-10-10 读取的该版本页面提炼；以后无需为了普通 Git 文案反复抓取参考页。用户要求重新对齐时再读取最新内容。

## 保留的写法

- 使用版本号和已知发布日期标识发布范围。
- 将影响已有消费者的兼容性变化放在最前，直接说明契约变化和需要调整的使用方式。
- 按功能、修复、性能、重构、文档、测试、CI 等类型排列；没有内容的分类不保留。
- 为每条写清模块范围和具体动作，避免宽泛的营销式评价。
- 以真实 commit、PR、issue 或迁移文档建立追溯关系。

## 跨场景适配

| 场景 | 继承的原则 | 调整 |
| --- | --- | --- |
| commit | 模块明确、行为具体、breaking 明示 | 压缩为一个主题；按需补正文和 footer |
| merge / PR / MR | 变化明确、影响明确、证据可查 | 围绕最终结果补充真实验证和兼容性 |
| tag | 版本身份、主要变化、升级提醒 | 用短文本 annotation；不混同托管平台 release |
| release / changelog | breaking 优先、分类条目、来源链接 | 汇总完整范围中的独立最终变化 |

该页说明本身不能证明当前仓库使用某种 commitlint 配置、版本策略或发布工具；不要据此要求项目安装 Conventional Commit 工具，也不要复制参考项目的实际变更、版本号和命令。

在此结构上增加“基于实际 patch、同组件基线、净变化去重、验证状态明确”的规则，作为当前 skill 的规范。这些是为跨场景使用加入的要求，不声称都是参考仓库的既有流程。
