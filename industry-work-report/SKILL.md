# 行业化工作报告与复盘生成器

把零散的工作记录整理成"符合用户所在行业主流风格"的日报/周报/月报/复盘，让上级或客户在 30 秒内看懂重点。

## 核心原则（所有行业通用）

1. **不编造**：素材里没有的事实、数据一律不写。提取不到就留空或写"待补充"，绝不为好看而硬编。
2. **结论先行**：首屏给最重要的结论/进展，细节往下展开。
3. **风险不藏**：卡点、延期、资源不足必须写清"具体卡点 + 影响 + 需要谁支持"。没有风险就写"无明显风险"，不硬凑。
4. **有依据才量化**：有数据时突出进度/产出/指标；无数据时保留文字结论或标注待补充，不为满足版式编造数字，也不把条目数量当作业务完成率。
5. **禁用模糊词**：不出现"略""稍""基本""大概""明天会更好"这类空话；模糊词超过 3 处即重写。
6. **把动作翻译成价值**：❌"完成接口联调" → ✅"支付接口联调按计划推进，完成度 80%，为周四提测扫清阻塞"。

## 工作流（七步，按序执行）

### Step 0：先识别预设，再开始处理

当用户刚触发技能后直接贴入一大段工作记录、聊天摘录、任务列表或多日素材，且没有明确指定报告类型/行业/输出形式时，**先停在识别阶段，不生成最终报告**。以下任一情况视为“大段素材”：纯文本约 500 字以上、8 条以上工作条目、包含多个日期/项目，或同时出现完成事项、计划、问题和零散数据。

先从素材中推出一份可调整的“报告预设”，只写有依据的判断：

```text
我识别到的报告预设
- 报告类型：日报 / 周报 / 月报 / 复盘（依据：……）
- 时间范围：……（未识别到则标记“待确认”）
- 行业风格：……（依据：……）
- 汇报对象：直属上级 / 项目组 / 客户 / 对外（未识别到则“待确认”）
- 核心重点：……
- 风险与待协调：……（没有证据就写“待确认”，不写“无风险”）
- 输出形式：Markdown / 单个 HTML / 三套 HTML（默认 Markdown）
- 视觉模板：商务蓝 executive / 暖白 editorial / 深色 briefing（仅 HTML 生效）

请回复“确认”，或直接修改其中任意一项；确认后我再整理正式报告。
```

预设只做分类、归纳和缺口标记，不补写事实、不计算未提供的指标、不擅自把多日素材合并为某一种周期。用户回复“确认”“按这个来”或给出修改项后，才继续 Step 1–6。用户明确说“直接生成/不用确认”，或已经明确给出类型、行业和输出形式时，可跳过本步骤；素材很短且请求清晰时也直接处理。识别预设时只需展示关键判断，不要把整段原始素材重复一遍。

详细字段和确认写法见 `references/identification-preset.md`。

### Step 1：识别报告类型与输出形式

根据用户请求判定：日报 / 周报 / 月报 / 季报 / 复盘（项目复盘、阶段复盘）。拿不准就问一句。各类型结构差异见 `references/report-types.md`，生成前先读。

默认输出 Markdown。用户提到“日报转 HTML”“可视化日报”“展示模板”“网页汇报”时，读取 `references/html-visualization.md`，使用内置转换器生成可下载、可离线打开的单文件 HTML。已有完整日报仅转换展示时，保留其行业结构、原始事实与顺序，不必重新收集素材。用户未指定视觉风格时默认商务蓝；要求比较模板时生成三套及预览入口。若 Step 0 已确认预设，以确认后的类型、行业、周期、对象和输出形式为准。

### Step 2：识别行业（本 skill 的核心）

按以下优先级判定行业，只读命中的那一个行业参考文件：

1. 用户明确说了（如"我是做制造的""外企风格"）→ 直接采用。
2. 从素材关键词推断：
   - 出现 需求/Bug/联调/迭代/上线/OKR/灰度 → `references/industries/internet-tech.md`
   - 出现 客户拜访/线索/成交/商机/漏斗/渠道 → `references/industries/sales-marketing.md`
   - 出现 仓位/回撤/尽调/标的/净值/合规 → `references/industries/finance.md`
   - 出现 产线/良率/交付/工单/设备/安全巡检/BOM → `references/industries/manufacturing.md`
   - 出现 甲方/乙方/交付物/里程碑/投标/提案 → `references/industries/consulting.md`
   - 出现 处/科室/上级要求/贯彻/落实/意识形态 → `references/industries/gov-soe.md`
   - 出现 实验/论文/课题/导师/审稿/招生 → `references/industries/research-edu.md`
   - 出现 stakeholder/TL;DR/deadline/英文汇报语境 → `references/industries/foreign-enterprise.md`
   - 用户是创始人/小团队，素材提及融资/获客/MVP/增长验证 → `references/industries/startup.md`
3. 推断不出来：先查本文件末尾"已知用户行业记忆"和用户记忆/项目上下文；仍无法判定时用 `references/industries/general.md`，并在生成后问一句"你的行业/公司风格是什么？告诉我后我会按行业模板重写"。**把答案记录下来**（追加到本文件末尾），下次直接命中。

### Step 3：收集素材

按顺序收集，取到多少用多少：

- 用户本次对话里给的材料（口述、聊天记录粘贴、要点列表）。
- 用户已有的日报/周报（写月报前先找当月周报；写周报前先找本周日报，本地 `.workbuddy/memory/` 或用户指定路径）。
- 技术类工作可主动检查：`git log --since="..."` 提交记录、项目 README/任务清单。
- 素材不足时，列出缺失项让用户一次性补充，或给出带 `[待补充]` 占位的初稿，不反复追问。

### Step 4：提炼整理

- 归类去重：同一件事只留一次；按"完成 / 进行中 / 计划 / 风险"分类。
- 提炼价值：按核心原则第 6 条翻译。
- 数据分列：所有数字（进度%、数量、金额、时长）单独标注出处。

### Step 5：按行业模板生成

- 严格遵循 Step 2 命中的行业参考文件中的结构、用词风格、格式规范。
- 复盘类按该文件中的复盘框架（默认 GRAI）执行。
- 根据 Step 1 输出 Markdown 或 HTML。HTML 使用 `scripts/render_report.py` 与 `assets/html/` 中的模板资源，具体字段、命令和模板选择见 `references/html-visualization.md`。用户要求导出 Word/Excel/PPT 时，走对应 Office skill，模板内容不变。

### Step 6：自检后交付

对照检查清单（逐条核对，不过则改完再交）：

- [ ] 结论/核心进展在首屏 3 行内可见
- [ ] 数据有出处；无数据时未编造数字、进度或趋势
- [ ] 风险有"描述 + 影响 + 需要的支持"三要素（或明确写"无明显风险"）
- [ ] 下期计划具体（任务 + 完成标准 + 时间点），不超过 5 条
- [ ] 无模糊词、无空话、无编造
- [ ] 敏感信息（客户全名、金额、内部数据）在对外场景做了脱敏
- [ ] 行业风格核对：用词、结构、语气符合该行业参考文件
- [ ] 若输出 HTML：已打开检查桌面/窄屏排版；打印可读；模板未引入外部资源；原文内容无遗漏；指标与进度均有来源，示例数据未混入真实日报

交付时附一句说明：本次按「XX行业风格」生成，如需换风格（更正式/更精简/中英文）直接说。
