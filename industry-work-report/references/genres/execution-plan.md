# 执行计划：项目计划 / 实施方案 / 上线计划 / 迁移方案 / 活动方案

## 定位

方向和目标已定后，把一次性项目、迁移、发布、活动或跨团队变更转成可协同推进的**交付物、依赖、里程碑与验收**。

**排除**：还在选方向或申请资源 → `proposal.md`；报告当前进展 → `status-report.md`；重复性的固定流程 → 操作手册（不在本技能范围）。

## 硬约束

| 项 | 规则 |
| --- | --- |
| 写作 | 以交付和判断为单位，具体、紧凑；可信度来自依赖、产能和验收闭环，不来自章节数量或没有依据的精确日期 |
| 逻辑 | 已批准的目标、成功标准、范围与约束 → 交付物 / 工作流 → 依赖与关键路径 → 带退出条件的里程碑 → 负责人 / 接口 / 资源 → 风险触发与备选 → 变更与验收机制 |
| 事实 | 区分已确认承诺、估算、假设和待定项；时间、负责人、预算、产能、依赖和验收方可追溯且算术相容 |
| 失败 | 任务清单冒充计划、活动没有交付物和完成定义、里程碑只是日期、排期不服从依赖与产能、所有事项同优先级、风险无预警信号和动作 |

## HTML 组件配方

| 位置 | 组件 |
| --- | --- |
| 首屏 | `summary`（目标 + 关键日期）+ `kpis`（周期 / 人力 / 预算）+ `highlights`（关键路径 / 最大风险） |
| 范围 | `grid`（范围内 / 范围外） |
| 工作分解 | `table`（交付物 / 负责人 / 完成定义）或 `kanban` |
| 排期 | `gantt`（按工作流 `group`，里程碑 `milestone`） |
| 阶段门 | `steps`（每步的退出条件写在 `desc`） |
| 分工 | `table`（RACI：负责 / 批准 / 咨询 / 知会） |
| 风险 | `risks`（写预警信号与备选）+ `risk-matrix` |
| 验收 | `checklist` |
