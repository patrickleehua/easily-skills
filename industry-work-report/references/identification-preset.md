# 大段素材识别预设

这一步的目标是让用户在正式整理前看到“你打算怎么整理”。它不是报告草稿，也不是再次索要全部素材。只输出基于原文的判断和待确认缺口。

## 何时触发

优先触发于以下组合：

- 用户刚触发本技能，随后直接粘贴大量工作内容；
- 没有明确说日报、周报、月报、复盘或 HTML；
- 没有明确行业、汇报对象或时间范围。

500 字、8 条、多个日期/项目只是辅助阈值，不是硬规则。短内容但明显存在多个可能的整理方式时，也应先给预设。用户已经说“把下面内容整理成互联网研发周报并输出 HTML”时，不再重复确认已明确的字段，只补充仍缺失且会改变结果的字段。

## 识别顺序

1. 从日期密度、词语和任务跨度推断日报/周报/月报/复盘；无法区分就写“待确认”。
2. 按 `SKILL.md` 的关键词规则推断行业；证据不足时用“通用职场风格（待确认）”。
3. 从“领导/客户/项目组/对外”等称谓推断汇报对象；没有就标记待确认。
4. 从用户显式要求或上下文判断 Markdown/HTML；没有要求时默认 Markdown。
5. 仅从原文摘出重点事项、已出现的数据和风险；不把条目数量当完成量，不从“推进中/差不多”猜百分比。

## 预设字段

```text
报告类型：……（依据：……）
时间范围：……（依据：……）
行业风格：……（依据：……）
汇报对象：……（依据：……）
核心重点：最多 3 条
风险与待协调：最多 3 条；没有证据则“待确认”
输出形式：Markdown / 单个 HTML / 三套 HTML
视觉模板：仅 HTML 填写 executive / editorial / briefing
```

“依据”应引用短关键词或日期范围，不复制大段原文。识别出多个合理候选时，列出最多两个候选并说明区别，例如“日报（单日动作）/周报（多日汇总）”。

## 用户确认后的动作

以下回复视为确认：`确认`、`按这个来`、`就按识别结果生成`。以下回复视为调整：`改成周报，行业按制造业，输出 HTML，用 briefing`。收到调整后，先把更新后的字段简短回显；如果调整已经足够明确，不必再次要求用户回复“确认”，直接生成。

如果用户只确认部分字段，例如“类型确认，行业不确定”，保留已确认字段，对剩余字段使用通用模板并在结果中标注待补充。确认前不要生成正式 Markdown、HTML、指标卡或进度条。

## 示例

用户贴入一周内的研发任务、上线记录、Bug、测试数字和明日计划，但没有说明要写什么时：

```text
我识别到的报告预设
- 报告类型：周报（素材覆盖 9/1–9/7，包含多日完成项）
- 时间范围：2026/9/1–2026/9/7
- 行业风格：互联网研发（出现联调、Bug、上线、测试）
- 汇报对象：待确认
- 核心重点：支付联调、回归测试、验收准备
- 风险与待协调：验收账号开通（素材提到可能影响验收）
- 输出形式：Markdown
- 视觉模板：不适用

请回复“确认”，或直接修改其中任意一项；确认后我再整理正式报告。
```

用户回复“确认，用 briefing HTML 给项目组看”后，才生成项目组口径的 HTML，并沿用原文中有来源的数据。
