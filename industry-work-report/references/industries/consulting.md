# 咨询 / 专业服务（律所、会计、设计、外包交付）

## 风格要点（源自麦肯锡式结构化汇报）

- **金字塔原理**：结论 → 论据 → 建议，先总后分，每层要点不超过 3 条。
- **结论-论据-建议三段式**：先点明状态（"项目进度滞后 5%"），再给原因（"供应商交付延迟"），最后给方案（"调整计划，引入备用供应商"）。
- **客户/项目双视角**：进度条 + 客户满意度并重。
- **交付物导向**：一切围绕交付物（Deliverable）和里程碑，写清"交了什么、客户是否验收"。
- **工时即成本**：内部汇报附工时/人天投入，体现项目毛利视角。

## 周报模板

```markdown
# {项目名} 项目周报 - {日期} | {汇报人}

## 一、本周结论
{1 句话：项目整体状态 + 最重要的一件事}
（如：项目整体进度 78%，本周完成 X 交付物并通过客户验收，Y 风险需提前关注。）

## 二、关键进展（按里程碑）
| 交付物 | 里程碑 | 状态 | 本周动作 | 客户反馈 |
|--------|--------|------|----------|----------|

## 三、问题与建议
### 问题：{一句话}
- 论据：{事实/数据 1-3 条}
- 建议：{具体方案，含需要的资源}

## 四、下周计划
- {任务 + 交付标准 + 时间}

## 五、资源与决策请求（如有）
- {需要客户/上级拍板的事项，附推荐选项}
```

## 日/月差异

- **日报**（驻场/实施顾问常用）：当日客户现场动作 + 待客户确认事项 + 明日安排，突出"等待对方"的卡点。
- **月报**：加客户健康度（满意度/回款/续约信号）、项目毛利与人天消耗、里程碑偏差分析（计划 vs 实际）。

## 复盘要点

GRAI 基础上强化"假设验证"：当初的判断是什么 → 实际验证结果 → 方法论沉淀（哪些可以写进公司知识库/下次提案复用）。投标复盘要拆"赢单/丢单归因"。

## 用词风格

✅ 已交付 V2 方案并通过客户验收、客户决策人变更导致里程碑延迟 5 个工作日、建议引入备用供应商并调整排期
❌ 客户有点不满意、进度还行、下次注意
