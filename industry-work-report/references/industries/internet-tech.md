# 互联网 / 软件研发（含 AI/数据团队）

## 风格要点（源自大厂主流实践：字节/理想 OKR 周报、Google Snippets）

- **OKR 对齐**：有 OKR 体系时按 OPPP 结构组织——Objective/KR 进度 → 上周 Progress → 下周 Plan → Problem。
- **结论先行、数据说话**：每条进展都带完成度 %、数量、指标变化。
- **优先级标记**：任务标 P0/P1/P2；Bug 标 P0-P2。
- **风险不藏**：延迟写清"延迟几天、原因、需要谁支持"。
- **大白话**：避免堆黑话；必须用术语（灰度、AB 实验）时一句话解释。
- 理想/字节风格的"本周要事"变体：只写 3-5 件与 OKR 强相关的要事，每天 1-3 件"今日要事"。

## 周报模板

```markdown
# 周报 - {姓名} | {周一日期}~{周日日期}

## 本周核心结论
{1-2 句：最重要的成果/判断，让领导 30 秒看懂}

## 一、本周进展（按优先级）
### 关键进展
- [P0] {任务} — 完成度 {%} — {带来的结果/价值}
- [P1] {任务} — 完成度 {%} — {结果}
### Bug 修复 / 线上问题
- [P0/P1] {问题} — 影响范围 {X} — {已修复/进行中}
## 二、进行中
| 任务 | 进度 | 阻塞 | 预计完成 |
|------|------|------|----------|
## 三、风险与需要的支持
- {风险描述} — 影响 {延迟X天/阻塞X任务} — 需要 {谁/资源}
## 四、下周计划
- [ ] {任务} — 完成标准 {X} — {时间点}
## 五、数据指标（如有）
- {指标A}: {本周值}（环比 {+/-X%}）
```

## 日/月差异

- **日报**：只留"今日完成（3-5 条动作+结果）/ 进行中 / 明日计划 / 风险"，删除 OKR 和数据指标区块。
- **月报**：加"OKR/KR 达成度表（目标值/实际值/置信度）"、版本/迭代发布汇总、数据指标趋势表（周维度对比）。

## 复盘要点

按 GRAI；技术复盘额外要求：故障类写"时间线 + 根因 + 回滚点 + Action Items（监控/告警/预案）"；上线事故用 5W1H + 时间线。Action 落到"加 XX 告警""补 XX 预案"这类具体机制。

## 用词风格

✅ 联调完成 80%、上线后崩溃率下降 0.3pp、DAU 环比 +5%、P0 阻塞已解除
❌ 基本完成、进展顺利、效果不错、后续持续优化
